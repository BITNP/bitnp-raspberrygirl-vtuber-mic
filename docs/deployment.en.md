# Deployment

Configure `mic-stream` with `.env.example` as the variable reference. Mic connects only to Orchestrator. Set `ORCHESTRATOR_WS_URL` to the deployed Orchestrator WSS control endpoint and load `TRUSTED_LAN_TOKEN` from deployment secret storage. Never place a bearer token in the repository. Production requires WSS and a token. Mic does not generate or manage TLS certificates. Plain `ws://` is accepted only when `MIC_ALLOW_LOOPBACK_WS=true` and the URL host is `127.0.0.1`, `::1`, or `localhost`, solely for an explicit loopback test.

Set `ORCHESTRATOR_RTP_HOST` and `ORCHESTRATOR_RTP_PORT` to the UDP RTP ingress owned by Orchestrator. `MIC_RTP_BIND_HOST` and `MIC_RTP_BIND_PORT` select Mic's local UDP bind, with port `0` selecting an ephemeral port. `BITNP_MIC_RTP_STREAM_ID`, `BITNP_MIC_RTP_TIMESTAMP`, `BITNP_TRACE_ID`, and `BITNP_SESSION_ID` are required for each stream. `BITNP_MIC_RTP_TIMESTAMP` must be an unsigned 32-bit integer. For the onsite loop, `BITNP_SESSION_ID` and `BITNP_MIC_RTP_STREAM_ID` must exactly match Sound's `SOUND_SESSION_ID` and `SOUND_RTP_STREAM_ID`. Leave `MIC_MAX_CAPTURE_BLOCKS` unset for continuous capture, or set a positive integer for a bounded verification run.

Live capture uses `sounddevice` and PortAudio. Run `uv sync --locked` before deployment. On Windows and macOS, allow the process running `mic-stream` to access the microphone. On Linux, install the distribution's PortAudio runtime and grant the service account recording permission. Omit `BITNP_CAPTURE_DEVICE` or set it to `default` for the host default input. An available device index or name query is also accepted.

Start the runtime with `uv run mic-stream`. It binds UDP, sends the authenticated `media.rtp.source.register` control event, waits for the matching `media.rtp.source.ready` event, then sends one V2/PT96/L16 RTP packet to Orchestrator for every complete 16 kHz mono block. Each packet carries 320 samples, or 20 ms, of L16 audio. Verify a real deployment by confirming on Orchestrator that the WSS bearer authentication succeeds, the registered stream and SSRC receive `media.rtp.source.ready`, and the configured UDP ingress receives RTP frames. Mic has no onsite mode setting and never connects directly to Sound.
